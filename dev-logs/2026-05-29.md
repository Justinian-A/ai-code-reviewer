# 开发日志 - 2026年5月29日

## 项目概述

AI Code Reviewer是一个基于AI的代码审查工具，专注于GitHub Pull Request的自动化分析。工具结合AST静态分析与LLM语义理解，能够识别人工审查容易遗漏的安全漏洞、逻辑错误和架构问题。

**项目地址**: https://github.com/Justinian-A/ai-code-reviewer

## 技术架构

```
用户层
├── CLI (Click + Rich)
└── Web (FastAPI + Bootstrap 5 + Jinja2)

核心层
├── GitHub客户端 (PyGitHub + httpx)
├── AST分析器 (Tree-sitter)
├── LLM审查器 (LiteLLM)
└── 报告生成器

数据层
├── SQLite数据库
└── YAML配置文件
```

**数据流向**

1. 用户提交PR URL
2. GitHub客户端拉取PR元数据和diff
3. AST分析器解析代码结构，识别静态问题
4. LLM审查器分析diff语义，检测风险
5. 合并两路结果，去重排序
6. 生成结构化报告输出

## 遇到的问题与解决方案

**1. Tree-sitter语言包安装**

问题: tree-sitter的Python绑定在不同平台上安装方式不一致，语言 grammar需要单独编译。

解决: 使用预编译的wheel包，在pyproject.toml中指定兼容版本范围，避免用户手动编译。

**2. LiteLLM模型名称映射**

问题: 不同AI提供商的模型命名规范不同，用户容易配置错误。

解决: 在配置层建立provider到model的映射表，提供合理的默认值，配置校验时给出明确提示。

**3. GitHub API速率限制**

问题: 大型PR可能触发GitHub API速率限制。

解决: 实现请求缓存，对已获取的数据避免重复请求；添加速率限制检测和自动重试逻辑。

**4. Web界面会话管理**

问题: Web界面需要管理用户的API配置，但不适合写死在配置文件里。

解决: 使用SQLite存储用户配置，支持通过Web界面修改，与CLI配置独立管理。
